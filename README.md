**Що зрозумів про FixedUpdate і колайдери:**
* `Update()` викликається щокадру і слугує для зчитування вводу з клавіатури, тоді як `FixedUpdate()` працює з фіксованим часовим кроком фізичного рушія (50 разів на секунду) і призначений для фізичних обчислень.
* Зміна `transform.position` телепортує об'єкт в обхід фізики безпосередньо всередину колайдера, після чого рушій виштовхує його назад — це і є причиною тремтіння. Метод `MovePosition()` переміщує фізичне тіло за допомогою рушія з урахуванням зіткнень.
* Для тайлів підлоги обов'язково встановлюється `Collider Type = None`, інакше гравець застрягатиме на кожній плитці. `Composite Collider 2D` з операцією `Merge` об'єднує окремі колайдери тайлів води в один суцільний контур без відчутних стиків.

**Що в рівні вийшло не так, як у фізичному паспорті, і чому:**
Розташування деяких декорацій та водойми довелося трохи змінити порівняно з початковим планом, щоб залишити достатньо ширини для вільного проходу персонажа й уникнути занадто вузьких місць між колайдерами.

* Налаштовано фізичні шари `Character` та `Projectiles` у `Physics 2D Layer Collision Matrix`, вимкнувши зіткнення між ними.
* Реалізовано функцію `Fix()`, яка зупиняє ворога (`simulated = false`), вимикає шкоду та запускає анімацію полагодження.

**Що не вийшло або забрало найбільше часу:**
Найбільше часу пішло на коректне налаштування Physics Collision Matrix для шарів `Character` x `Projectiles`, щоб снаряд не знищувався одразу при вильоті з колайдера робота, а також на вирішення проблеми з `NullReferenceException` шляхом ініціалізації `rigidbody2d` у методі `Awake()` замість `Start()`.

**Що зрозумів про Animator, шари й Awake:**
* `Awake()` викликається у момент створення об'єкта через `Instantiate()`, що дозволяє отримати компоненти до того, як інші скрипти викликають методи об'єкта (наприклад, `Launch()`).
* Фізичні шари (Layers) дозволяють гнучко фільтрувати колізії між різними групами об'єктів без необхідності писати додаткові умови в коді.
* `Blend Tree` дозволяє плавно змішувати анімаційні кліпи на основі числових параметрів напрямку руху.

**Які Speed і Change Time обрав і для якого гравця:**
Для стандартного ворога обрано `Speed = 1.0` та `Change Time = 3.0` (довжина маршруту 3 одиниці). Це створює зрозумілий ритм патрулювання, який легко прорахувати.

**Що робить мій снаряд з ворогом і як це пасує до моєї рамки:**
Снаряд не знищує ворога, а лагодить його (викликає `Fix()`), повертаючи зламану машину до нормального стану. Це повністю відповідає гуманному та творчому сетингу гри `Robot Repair`.
